产品与用户调研

九号（Segway-Ninebot）两轮车产品矩阵、屏幕形态与主题生态现状

1.1 与显示屏相关的产品矩阵

主题的载体是仪表屏。九号两轮车按「屏幕能力」可分为三类：7 英寸动态仪表（旗舰，支持动效皮肤）、彩屏仪表（4.3 英寸级 TFT，支持静态/轻动效皮肤）、基础屏（点阵/单色，暂不支持主题）。设计资源应优先投向前两类。

把调研结论收敛为可指导设计的定位

2.1 目标用户定位

主题商城的核心付费人群定义为：18–30 岁、持有彩屏或 7 英寸动态仪表车型的九号车主。他们已为「个性化」支付过硬件溢价（如联名款），因此对 6 元级的软件皮肤几乎不存在决策阻力。

细分人群占比预期核心诉求付费敏感度
年轻男性通勤 + 性能党主力盘（约 55%）酷、速度感、数据专业感低，看重「值不值这个调性」
女性用户增长盘（约 30%）颜值、情绪价值、拍照好看中，看重「一眼心动」
学生 / 尝鲜党机会盘（约 15%）低价、新鲜、可炫耀高，6 元是理想入口价

2.2 六类真实使用场景

场景典型时刻对屏幕的核心要求
城市通勤早晚高峰、短途代步时速/电量一眼可读，强光下不反白
夜间骑行加班晚归、夜骑低亮度不刺眼，暗色不晃眼
周末跑山 / 长距离环湖、城郊路线功率、里程、能耗数据完整

设计硬约束由此推出：无论风格多强，时速、电量、里程、档位、转向/故障提示等安全相关字段必须始终清晰可见且不被遮挡。这是审核与用户口碑的共同底线。

3.2 共同设计规范（三款通用）

  • 安全字段优先：时速、电量、里程、档位、转向指示、故障码在全部主题与全部状态下均不得被装饰元素遮挡，且不得与背景同色。
  • 多屏适配：每款主题需同时交付 7 英寸动态仪表与彩屏（4.3 英寸级）两套画布版本，圆角半径、安全区、字段密度分别处理，禁止简单缩放。
  • 一键识别：骑行中 1 秒内应能读到时速与电量，时速字号为画布内最大元素。
  • 强光可读：正午直射下关键信息对比度不低于 4.5:1，禁止纯浅色低对比配色承担关键数据。
  • 双端联动：仪表皮肤与 App 皮肤保持同一视觉体系，切换后 App 界面同步生效。
  • 版权干净：仅使用自有或已授权字体、图形、插画，不使用任何未授权 IP 形象（含动漫角色、游戏素材、品牌 logo）。

五个测试维度、五步测试流程、可量化的通过标准

4.1 测试内容（五个维度）

维度测什么方法
兼容与适配 机型/屏型适配、固件与 App 版本兼容、安全区与圆角、各数据字段是否完整显示 真机矩阵测试，逐屏型截图核对
可读性 强光/夜间/雨天可读性、字号与对比度、色弱友好、1 秒识别率、动效是否干扰读数 户外实景测试 + 计时识别测试 + 对比度取值
性能与稳定 帧率、切换耗时、内存与耗电、长时间骑行稳定性、连续切换是否崩溃 性能埋点 + 2 小时连续骑行 + 100 次循环切换

4.2 测试流程（五步）

  1. 内部自测设计与制作人员按自检清单逐项核对（字段完整、无遮挡、无错别字、素材齐全）。3 款主题各产出《自测记录表》。
  2. 真机适配测试在覆盖 7 英寸动态仪表与彩屏两类屏型的真机矩阵上安装验证，每款主题至少覆盖 3 台不同车型设备，逐屏截图归档。
  3. 小范围内测通过九号出行 App 测试中心 / 圈子 / 九友会渠道招募 20–50 名车主，试用 7 天，回收问卷与使用反馈（含夜间、雨天、强光实拍）。
  4. 修复与回归反馈按 P0 / P1 / P2 分级录入看板，逐项修复并回归验证；P0 必须清零，P1 必须收敛到有明确结论。
  5. 提审前终检按平台审核规则做最终合规与规范核对，产出《测试报告》与《终检清单》，随后提交审核。

未达标怎么办

任一主题未达标即不进入提审。优先级：可读性 > 功能适配 > 合规 > 性能 > 用户反馈。若仅用户反馈未达标但硬指标全部通过，允许以降价或调整封面/描述后重新内测，而非直接放弃。

上架流程与渠道

唯一官方通道：九号主题开发者平台 → 九号出行 App 主题商城

5.1 上架流程（八步）

  1. 入驻申请在九号主题开发者平台提交入驻意向与资质/作品集，等待平台资格审核。被驳回会注明原因，需按反馈改进后重新提交。
  2. 获得开发者身份审核通过后进入工作台，确认编辑器权限、素材规范与「适配机型 / 屏幕规格」清单。
  3. 主题开发使用平台的可视化、无代码编辑器完成三款主题，含动效与多屏版本。
  4. 上传主题并定价上传主题包，填写名称、简介、封面与适配机型，并将三款主题统一设定为 ¥6。
  5. 提交审核提交后进入平台审核，常规审核周期约 7 个工作日，遇问题可能延长。未通过可在工作台点击主题名称查看审核意见。
  6. 审核通过并上架通过后在九号出行 App 主题商城曝光，面向千万级 App 用户。
  7. 运营与迭代跟踪下载/购买与评价数据，做节日限定、季节版本、用户共创投票等持续运营。
  8. 自助结算按平台分润体系在开发者平台完成自助结算。

统一定价 ¥6 的三条理由：决策成本归零——6 元低于用户的比价阈值，购买动作不再需要「值不值」的判断；最大化装机与评价基数——三款站在同一起跑线，避免低价款吸走全部流量、高价款缺少曝光，而下载量与评分正是主题商城里最值钱的资产；差异由风格承担——三款的区分度来自视觉与场景，用户按审美而非预算选择，不会因为价格暗示而产生「低配」联想。

档位已对齐：¥6 属「精致进阶」，动效合规；IP 授权仍是最高优先项

平台价格区间 3–18 元分三档：基础简约 3–6 元（无 App 主题、无动效、无 IP）、精致进阶 6–12 元（含 App 主题或动态效果）、高端全配 12–18 元（App 主题 + 动态交互 / 正版授权 IP）。¥6 是精致进阶档的下限，三款主题都含动效，档位要求已完全对齐——原先「按 3 元申报就得砍动效」的矛盾解除。

  • 动效：合规。精致进阶档允许动效，A 款云带横移、B 款图腾环点亮、C 款时段与天气切换可全部保留。
  • IP 授权：与定价无关，需单独解决。「正版授权 IP」在平台档位表里属高端全配 12–18 元的特征；更关键的是，授权是使用前提，跟标价多少没有关系。未经授权使用他人作品名称、角色形象或标志性道具，会触发「素材非原创比例 >30% 即不视为原创」的红线，属单项否决。
  • 建议：① 拿到正版授权 → 价格上探至 12–18 元高端全配档；② 改为「同题材原创设计」→ 保留仙侠 / 洪荒的意境与配色，不使用 IP 名称，价格维持 ¥6；③ 先按 ¥6 提交原创版本，授权谈成后再上架 IP 版并调价（平台支持上架后改价）。

统一定价的代价与应对

  • ARPU 上限被压低。缺少高价款，单用户收入天花板降低。应对：把收入预期从「单价」转向「装机量 × 复购」，用季节限定、节日主题持续拉动二次购买。
  • 无法用价格验证旗舰价值。制作成本最高的 C 款与 A 款同价，投入产出比不对等。应对：把 C 款明确定位为「差异化与口碑资产」而非利润款，它的回报体现在评分、分享与拉新上。
  • 失去打包促销空间。三款同价无法做「¥6 全套包」式组合。应对：改用「集齐三款解锁限定款」「节日限免」等运营手段替代。
  • 好消息是可逆。平台的主题类资源支持上架后修改定价，统一 ¥6 是随时可调整的决策——若后续数据证明需求分层明显，可单独上调高成本款。

关于收入的说明

平台采用「优厚分润体系」，但具体分成比例、结算周期、最低结算门槛均未公开。因此本文中的价格是用户侧售价，不含分润测算。建议入驻后第一时间确认分润条款，再评估 6 元定价的可持续性。
